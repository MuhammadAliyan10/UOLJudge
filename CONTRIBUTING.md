# Contributing to UOLJudge

Thank you for your interest in contributing to UOLJudge! We welcome contributions from the community to help make this the best competitive programming platform.

## Code of Conduct

By participating in this project, you agree to abide by our Code of Conduct. We expect all contributors to treat each other with respect and professionalism.

## How to Contribute

### Reporting Bugs

1.  **Check existing issues** to see if the bug has already been reported.
2.  **Open a new issue** if it hasn't. Provide a clear title, detailed description, steps to reproduce, and any relevant logs or screenshots.

### Suggesting Enhancements

1.  **Open a new issue** describing your feature request.
2.  Explain why this feature would be useful and how it should work.

### Submitting Pull Requests

1.  **Fork the repository** and create a new branch for your feature or fix.
    ```bash
    git checkout -b feature/my-new-feature
    ```
2.  **Make your changes** and ensure they follow the project's coding style.
3.  **Test your changes** locally to ensure they work as expected.
4.  **Commit your changes** with descriptive commit messages.
    ```bash
    git commit -m "feat: add new leaderboard filter"
    ```
5.  **Push to your fork** and submit a Pull Request to the `main` branch.
    ```bash
    git push origin feature/my-new-feature
    ```
6.  **Wait for review**. We will review your PR and provide feedback.

## Development Setup

Please refer to the [DEPLOYMENT.md](DEPLOYMENT.md) guide for instructions on setting up the development environment.

## Style Guide

- Use **TypeScript** for all new code.
- Follow the existing directory structure.
- Use **Prettier** for code formatting.
- Ensure all new components are responsive and accessible.
